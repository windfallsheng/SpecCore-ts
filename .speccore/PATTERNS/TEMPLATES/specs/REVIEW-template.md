## 1. 代码质量

### 1.1 编码规范

| 序号 | 检查项 | 严重程度 | 检查方式 | 说明 |
|------|--------|---------|---------|------|
| CQ-001 | 代码符合团队统一风格（ESLint/Checkstyle/Prettier） | 🔴 强制 | 静态分析工具 | CI Pipeline 自动检查，不通过则阻断合并 |
| CQ-002 | 类命名遵循约定（如 Controller→XXXController） | 🔴 强制 | 人工审查 | 统一术语：Service/Repository/DTO/VO/Utils |
| CQ-003 | 魔法数字提取为常量 | 🟡 建议 | 人工审查 | 如 `if (status == 1)` 应改为 `if (status == OrderStatus.PAID)` |
| CQ-004 | 日志使用占位符而非字符串拼接 | 🟡 建议 | 人工审查 | `log.info("orderId={}", id)` 而非 `log.info("orderId=" + id)` |
| CQ-005 | 注释与代码一致，无过时注释 | 🟡 建议 | 人工审查 | 删除被注释掉的 Dead Code |
| CQ-006 | 数据库操作无 N+1 查询 | 🔴 强制 | 人工审查 + SQL 监控 | Hibernate 中的 lazy loading 陷阱 |
| CQ-007 | 枚举值不直接硬编码 | 🟡 建议 | 静态分析 | 使用枚举类型而非字符串/数字常量 |

### 1.2 复杂度控制

| 序号 | 检查项 | 阈值 | 测量方法 |
|------|--------|------|---------|
| CQ-010 | 单方法行数 | ≤ 50 行 | SonarQube / CodeClimate |
| CQ-011 | 圈复杂度 (Cyclomatic Complexity) | ≤ 10 | SonarQube |
| CQ-012 | 单类方法数 | ≤ 20 | SonarQube |
| CQ-013 | 嵌套层级 | ≤ 4 层 | 人工审查 + ESLint max-depth |
| CQ-014 | 参数个数 | ≤ 5 | 超过建议封装为 DTO |

### 1.3 重复代码

| 序号 | 检查项 | 严重程度 | 处理方式 |
|------|--------|---------|---------|
| CQ-020 | 相同逻辑重复出现 ≥ 3 次 | 🔴 强制 | 抽取为公共方法 |
| CQ-021 | SQL 条件拼接重复 | 🟡 建议 | 使用 QueryDSL / MyBatis 复用 |
| CQ-022 | 异常处理模板重复 | 🟡 建议 | 使用 AOP / 全局异常处理器 |

## 2. 安全审查

### 2.1 注入类攻击

| 序号 | 检查项 | 攻击场景 | 防护要求 | 验证方法 |
|------|--------|---------|---------|---------|
| SEC-001 | SQL 注入 ⭐ | 用户输入拼接到 SQL | 全部使用参数化查询 / ORM | 代码审查 + OWASP ZAP |
| SEC-002 | XSS 跨站脚本 | 用户输入回显到页面 | 输出编码 + CSP 头部 | DOMPurify / Thymeleaf 自动转义 |
| SEC-003 | 命令注入 | `Runtime.exec(userInput)` | 禁止拼接外部输入到系统命令 | 代码审查 |
| SEC-004 | XXE 外部实体注入 | XML 解析器配置不当 | `XMLInputFactory` 禁用 DTD | 检查 SAX/DOM 解析器配置 |
| SEC-005 | SSRF 服务端请求伪造 | 用户传入 URL | URL 白名单校验 + 内网地址过滤 | 代码审查 + 渗透测试 |
| SEC-006 | 路径遍历 | `../../etc/passwd` | 禁止拼接用户输入到文件路径 | `Paths.get().normalize()` |

### 2.2 认证与授权

| 序号 | 检查项 | 风险 | 检查要点 |
|------|--------|------|---------|
| SEC-010 | 接口鉴权完整性 ⭐ | 未授权访问 | 所有接口均需声明权限注解，默认拒绝 |
| SEC-011 | 越权检查 | 水平/垂直越权 | 资源归属校验（用户 A 只能操作自己的资源） |
| SEC-012 | JWT 过期处理 | Token 永不过期 | Access Token ≤ 2h，Refresh Token ≤ 7d |
| SEC-013 | 敏感操作二次确认 | 误操作或恶意操作 | 支付/退款/删除需二次确认 + 验证码 |
| SEC-014 | Session 固定攻击 | Session 劫持 | 登录后重新生成 Session ID |

### 2.3 敏感数据保护

| 序号 | 检查项 | 数据示例 | 防护措施 |
|------|--------|---------|---------|
| SEC-020 | 日志中无敏感信息 | 密码、Token、身份证号 | 日志脱敏 / @ToString.Exclude |
| SEC-021 | 前端不传输多余敏感字段 | 数据库中完整返回给前端 | DTO 裁剪 / @JsonIgnore |
| SEC-022 | 敏感配置不硬编码 | 数据库密码、API Key | 环境变量 / KMS / Vault |

## 3. 性能审查

### 3.1 数据库查询

| 序号 | 检查项 | 严重程度 | 检查要点 |
|------|--------|---------|---------|
| PERF-001 | 新 SQL 是否有索引覆盖 ⭐ | 🔴 强制 | EXPLAIN 分析，type 至少为 range，避免 ALL 全表扫描 |
| PERF-002 | 是否避免 SELECT * | 🟡 建议 | 仅查询需要的字段，减少数据传输 |
| PERF-003 | 大表查询必须有分页 | 🔴 强制 | LIMIT + OFFSET 或游标分页 |
| PERF-004 | 是否避免在 WHERE 子句中使用函数 | 🟡 建议 | `WHERE DATE(created_at) = '2026-01-01'` 应改写为 `WHERE created_at >= '2026-01-01' AND created_at < '2026-01-02'` |
| PERF-005 | 批量操作使用批处理 | 🟡 建议 | 避免循环单条 INSERT/UPDATE |

### 3.2 缓存使用

| 序号 | 检查项 | 检查要点 |
|------|--------|---------|
| PERF-010 | 高频查询是否添加缓存 | 同一查询 QPS > 100 需考虑缓存 |
| PERF-011 | 缓存 Key 设计是否合理 | 有命名空间、版本号，避免 Key 冲突 |
| PERF-012 | 缓存更新策略是否正确 | Cache-Aside / Write-Through / Write-Behind |
| PERF-013 | 是否考虑了缓存穿透/击穿/雪崩 | 布隆过滤器 / 互斥锁 / TTL 随机化 |

### 3.3 异步与并发

| 序号 | 检查项 | 检查要点 |
|------|--------|---------|
| PERF-020 | 非核心路径是否异步化 | 发送通知、写操作日志、数据上报等使用消息队列 |
| PERF-021 | 锁粒度是否合理 | 避免全局锁，使用行级锁（乐观锁/悲观锁） |
| PERF-022 | 线程池大小是否合理 | CPU 密集型 N+1，IO 密集型 2N+1（N=核心数） |

### 3.4 前端性能

| 序号 | 检查项 | 检查要点 |
|------|--------|---------|
| PERF-030 | 是否存在内存泄漏 | 组件卸载时清除 Timer/Event Listener |
| PERF-031 | 大列表是否使用虚拟滚动 | 超过 100 条数据使用 Virtual List |
| PERF-032 | 图片是否懒加载 | loading="lazy" 或 IntersectionObserver |

## 4. 可维护性

### 4.1 文档与注释

| 序号 | 检查项 | 严重程度 | 说明 |
|------|--------|---------|------|
| MAIN-001 | 新增接口是否有 API 文档 ⭐ | 🔴 强制 | Swagger/OpenAPI 注解，至少含路径、参数、响应 |
| MAIN-002 | 核心业务逻辑是否有注释 | 🟡 建议 | 解释"为什么"而非"做了什么" |
| MAIN-003 | README / Wiki 是否同步更新 | 🟡 建议 | 启动方式、配置项、依赖变更需同步文档 |
| MAIN-004 | 公共方法是否有 JSDoc/JavaDoc | 🟡 建议 | 至少描述参数含义和返回值 |

### 4.2 日志规范

| 序号 | 检查项 | 日志示例 |
|------|--------|---------|
| MAIN-010 | 关键业务节点有 INFO 日志 | `log.info("订单创建成功 orderNo={}, amount={}", orderNo, amount);` |
| MAIN-011 | 异常有 ERROR 日志含堆栈 | `log.error("支付回调处理失败 orderNo={}", orderNo, e);` |
| MAIN-012 | 日志包含 TraceID 便于链路追踪 | MDC 中注入 TraceID，日志 Pattern 配置 |
| MAIN-013 | 日志级别使用正确 | DEBUG 开发调试 / INFO 关键节点 / WARN 可恢复 / ERROR 需要人工介入 |

### 4.3 异常处理

| 序号 | 检查项 | 反模式 |
|------|--------|--------|
| MAIN-020 | 不吞异常（空 catch 块） | `catch (Exception e) { /* ignore */ }` |
| MAIN-021 | 不抛裸 RuntimeException | 应使用业务异常 `OrderNotFoundException` |
| MAIN-022 | 资源必须释放（IO/连接） | try-with-resources 或 finally 关闭 |
| MAIN-023 | 异常信息对用户友好 | 不暴露堆栈，提示用户可理解的信息 |

### 4.4 监控与告警

| 序号 | 检查项 | 说明 |
|------|--------|---------|
| MAIN-030 | 新增接口是否接入 Metrics | 接口调用次数、延迟、错误率需上报 Prometheus |
| MAIN-031 | 关键业务指标是否埋点 | 下单量、支付成功率等业务指标 |
| MAIN-032 | 是否有健康检查接口 | `/actuator/health` 含 DB/Redis/Kafka 连通性 |

## 5. 数据库变更审查

### 5.1 DDL 检查

| 序号 | 检查项 | 严重程度 | 说明 |
|------|--------|---------|------|
| DB-001 | 所有表必须有主键 | 🔴 强制 | InnoDB 下无主键会导致性能问题 |
| DB-002 | 字符集使用 utf8mb4 | 🔴 强制 | 支持 emoji 和生僻字 |
| DB-003 | 字段有默认值或允许 NULL | 🟡 建议 | NOT NULL 字段必须有 DEFAULT 值 |
| DB-004 | 字段有合适的 COMMENT | 🟡 建议 | 方便后续维护和数据字典生成 |
| DB-005 | 分库分表键是否合理 | 🔴 强制 | 需评估数据倾斜和跨库查询场景 |

### 5.2 索引检查

| 序号 | 检查项 | 说明 |
|------|--------|------|
| DB-010 | 新表索引是否与查询场景匹配 ⭐ | 使用 EXPLAIN 验证，联合索引遵循最左前缀 |
| DB-011 | 是否避免冗余索引 | 已有 `idx(a,b)` 则不必再建 `idx(a)` |
| DB-012 | 是否避免过多索引 | 单表索引数建议 ≤ 5，写入密集型建议 ≤ 3 |
| DB-013 | 大表 DDL 是否使用 Online DDL | 如 pt-online-schema-change 或 gh-ost |

### 5.3 SQL 变更检查

| 序号 | 检查项 | 说明 |
|------|--------|------|
| DB-020 | 大表 UPDATE/DELETE 是否分批执行 | 避免长事务锁表，每批 ≤ 5000 行 |
| DB-021 | 是否避免隐式类型转换 | `WHERE varchar_col = 123` 会导致索引失效 |
| DB-022 | JOIN 是否使用正确的驱动表 | 小表驱动大表，被驱动表 JOIN 列有索引 |
