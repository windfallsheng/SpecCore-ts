# 测试计划模板

> 本模板指导如何撰写专业的测试计划，覆盖后端 + 前端各端。
> 不是填空表 — 根据需求自由撰写，但必须覆盖以下维度。

## 写作原则

1. **按端分章节**：后端、各前端分别撰写，不要混在一起
2. **用例可执行**：每个用例必须有前置条件、操作步骤、预期结果
3. **优先级分层**：P0 核心流程 → P1 重要分支 → P2 边界/异常

## 文档结构

### 1. 测试范围与策略

| 测试类型 | 覆盖范围 | 工具/框架 | 执行时机 |
| :--- | :--- | :--- | :--- |
| 单元测试 | 核心业务逻辑 | Jest / JUnit | 每次提交 |
| 接口测试 | 全部 API | Postman / Supertest | PR 合并前 |
| E2E 测试 | 核心业务流程 | Cypress / Playwright | 发版前 |
| 页面测试 | 各端 UI 交互 | 手动 + 截图对比 | 每轮迭代 |

### 2. 后端接口测试

按功能模块组织，每个接口至少包含：

| 用例 ID | 接口 | 场景 | 前置条件 | 请求参数 | 预期结果 | 优先级 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| TC-001 | POST /api/xxx | 正常创建 | 用户已登录 | `{...}` | 200 + 返回新记录 | P0 |
| TC-002 | POST /api/xxx | 参数缺失 | 用户已登录 | `{}` | 400 + 错误提示 | P0 |
| TC-003 | POST /api/xxx | 无权限 | 未登录 | `{...}` | 401 | P0 |
| TC-004 | POST /api/xxx | 重复数据 | 已存在同名记录 | `{...}` | 409 + 冲突提示 | P1 |

**后端测试必覆盖维度：**
- ✅ 正常 CRUD 流程
- ✅ 参数校验（必填/类型/长度/范围）
- ✅ 鉴权（未登录/无权限/Token 过期）
- ✅ 并发与幂等（重复提交/竞态条件）
- ✅ 分页/排序/过滤
- ✅ 错误码一致性
- ✅ 事务回滚（部分失败场景）
- ✅ 边界值（最大长度/空值/特殊字符）

### 3. 前端页面测试

**按端分章节撰写**（如 admin 端、H5 端分别写）

#### 3.1 {端名} 页面流转测试

| 用例 ID | 页面 | 操作路径 | 预期结果 | 优先级 |
| :--- | :--- | :--- | :--- | :--- |
| FT-001 | 列表页 | 进入 → 筛选 → 翻页 | 数据正确展示 | P0 |
| FT-002 | 表单页 | 填写 → 校验 → 提交 → 跳转 | 成功提示 + 跳转 | P0 |
| FT-003 | 详情页 | 列表点击 → 详情 → 返回 | 数据完整 + 返回正常 | P0 |

#### 3.2 {端名} 交互测试

| 用例 ID | 组件 | 交互场景 | 预期行为 | 优先级 |
| :--- | :--- | :--- | :--- | :--- |
| UI-001 | 搜索框 | 输入 → 防抖 → 请求 | 300ms 防抖，结果刷新 | P1 |
| UI-002 | 弹窗 | 打开 → 填写 → 取消 | 数据不提交，弹窗关闭 | P1 |
| UI-003 | 按钮 | 快速双击 | 防重复提交，只发一次请求 | P0 |

#### 3.3 前端四态测试（每个页面必覆盖）

| 状态 | 描述 | 预期 UI |
| :--- | :--- | :--- |
| 加载中 | 数据请求中 | 骨架屏 / Loading 动画 |
| 正常态 | 数据加载成功 | 正确渲染数据 |
| 空态 | 无数据 | 空状态插画 + 引导文案 |
| 错误态 | 请求失败 | 错误提示 + 重试按钮 |

#### 3.4 前端专项测试

- **响应式**：不同屏幕尺寸下的布局表现
- **兼容性**：目标浏览器/设备列表
- **性能**：首屏加载时间、大列表滚动流畅度
- **无障碍**：键盘导航、屏幕阅读器（如需要）

### 4. E2E 端到端测试

跨端核心业务流程测试：

| 用例 ID | 业务流程 | 涉及端 | 步骤 | 预期结果 |
| :--- | :--- | :--- | :--- | :--- |
| E2E-001 | 完整业务流程 | H5 → 后端 → Admin | 1. H5 提交 → 2. 后端处理 → 3. Admin 查看 | 全链路数据一致 |

### 5. 测试数据与环境

| 环境 | 用途 | 数据要求 |
| :--- | :--- | :--- |
| 开发环境 | 自测 | 基础测试数据 |
| 测试环境 | QA 验证 | 完整业务数据 + 边界数据 |
| 预发布 | 上线前验证 | 生产数据脱敏副本 |

### 6. 准入/准出标准

- **准入**：编译通过、Lint 通过、单元测试 100% 通过
- **准出**：P0 用例 100% 通过、P1 用例 ≥ 95% 通过、无 P0/P1 级 Bug
