## 1. 文档概述

### 1.1 项目背景

<!-- 描述业务背景、要解决的问题、目标用户群体 -->

本项目旨在构建一个面向 C 端用户的电商订单管理系统，解决当前订单处理流程中人工操作占比高、异常订单流转慢的问题。目标用户为平台运营人员和终端消费者。

### 1.2 核心目标

| 目标 | 指标 | 目标值 |
|------|------|--------|
| 提升订单处理效率 | 单笔订单处理时间 | 由平均 5 分钟降低至 30 秒 |
| 降低异常订单率 | 月异常订单占比 | 由 8% 降低至 2% 以下 |
| 提升用户满意度 | NPS 评分 | 达到 60 分以上 |

### 1.3 需求范围

- **包含范围**：订单创建、支付处理、物流跟踪、售后工单
- **不包含范围**：商品管理后台、供应商管理、财务对账系统
- **关联系统**：用户中心、支付网关、物流平台

## 3. 接口分析

### 3.1 创建订单接口

- **接口路径**: `POST /api/v1/orders`
- **认证方式**: Bearer Token (JWT)
- **幂等性**: 通过 `Idempotency-Key` Header 保证

**请求示例**:

```json
{
  "customerId": "cust_123456",
  "items": [
    {
      "skuId": "SKU-001",
      "quantity": 2,
      "unitPrice": 99.00
    }
  ],
  "shippingAddress": {
    "recipient": "张三",
    "phone": "13800138000",
    "province": "广东省",
    "city": "深圳市",
    "district": "南山区",
    "detail": "科技园路1号创新大厦12F"
  },
  "couponCode": "PROMO2026",
  "remark": "请发顺丰快递"
}
```

**响应示例（成功）**:

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "orderId": "ORD-20260115-001",
    "orderStatus": "PENDING_PAYMENT",
    "totalAmount": 198.00,
    "discountAmount": 20.00,
    "actualAmount": 178.00,
    "expireTime": "2026-01-15T12:30:00+08:00",
    "createdAt": "2026-01-15T12:00:00+08:00"
  }
}
```

**响应示例（失败）**:

```json
{
  "code": 40001,
  "message": "商品 SKU-001 库存不足，当前库存: 1",
  "data": null
}
```

### 3.2 接口汇总表

| 接口路径 | 方法 | 说明 | 调用方 | 超时(ms) | 限流(QPS) |
|----------|------|------|--------|----------|-----------|
| `/api/v1/orders` | POST | 创建订单 | 前端/小程序 | 3000 | 1000 |
| `/api/v1/orders/{id}` | GET | 查询订单详情 | 前端/小程序 | 1000 | 5000 |
| `/api/v1/orders/{id}` | PUT | 修改订单信息 | 前端 | 2000 | 500 |
| `/api/v1/orders/{id}/cancel` | POST | 取消订单 | 前端 | 2000 | 300 |
| `/api/v1/payments` | POST | 发起支付 | 前端 | 5000 | 800 |
| `/api/v1/payments/callback` | POST | 支付回调 | 支付网关 | 5000 | 2000 |
| `/api/v1/refunds` | POST | 申请退款 | 前端 | 3000 | 200 |
| `/api/v1/logistics/{orderId}` | GET | 查询物流 | 前端 | 2000 | 3000 |

## 5. 业务规则矩阵

| 编号 | 规则描述 | 触发条件 | 执行动作 | 异常处理 |
|------|---------|---------|---------|---------|
| BR-001 | 订单金额不得小于 0.01 元 | 创建订单时校验 | 拒绝创建并返回错误 | 提示"订单金额无效" |
| BR-002 | 支付超时自动取消订单 | 订单创建后 30 分钟未支付 | 定时任务更新状态为 CANCELLED | 释放库存，通知用户 |
| BR-003 | 同一 SKU 不允许超卖 | 下单时扣减库存 | 乐观锁扣减，失败则回滚 | 返回"库存不足" |
| BR-004 | 已发货订单不可取消 | 用户点击取消时校验 | 拒绝取消并提示 | 引导用户走退款流程 |
| BR-005 | 优惠券仅限同一订单使用一次 | 下单时校验 | 标记优惠券已使用 | 提示"优惠券不可用" |
| BR-006 | 退款金额不得高于实付金额 | 退款申请时校验 | 拒绝退款 | 提示"退款金额异常" |
| BR-007 | 收货地址必须包含省市区 | 创建/修改订单时校验 | 地址解析校验 | 提示补充完整地址 |

## 6. UI/UX 要点

### 6.1 页面清单

| 页面 | 终端 | 核心交互 | 加载方式 | 空状态处理 |
|------|------|---------|---------|-----------|
| 订单列表页 | 小程序 | 下拉刷新 + 状态 Tab 切换 | 分页加载，每页 20 条 | 显示"暂无订单"引导图 |
| 订单详情页 | 小程序 | 关键操作按钮突出（支付/取消/确认收货） | 全量加载 | 404 页 |
| 支付确认页 | 小程序 | 倒计时 + 明确支付金额 | 静态页面 | N/A |
| 运营订单管理 | Web 后台 | 批量操作 + 高级筛选 | DataTable 服务端分页 | 空表格提示 |

### 6.2 关键交互规则

<!-- 描述重要的交互逻辑 -->

- **支付倒计时**：订单创建后展示 30 分钟倒计时，剩余 5 分钟时 UI 强调提醒（颜色变为橙色）
- **操作确认**：取消订单、确认收货等不可逆操作需二次弹窗确认
- **Loading 态**：所有接口调用需有骨架屏或 Loading 动画，请求超过 3 秒需展示进度提示
- **异常反馈**：网络异常展示离线提示；接口报错展示 Toast 通知，错误信息需用户可理解

## 7. 非功能需求

### 7.1 性能指标

| 指标 | 要求 | 测量方法 |
|------|------|---------|
| 订单创建接口 P99 延迟 | ≤ 500ms | APM 监控 |
| 订单列表查询 P99 延迟 | ≤ 200ms | APM 监控 |
| 系统整体可用性 | 99.95% | 健康检查探针 |
| 并发支付处理能力 | 峰值 5000 QPS | 压测验证 |

### 7.2 安全要求

| 安全项 | 要求 | 实现方式 |
|--------|------|---------|
| 接口认证 | 所有接口需验证身份 | JWT Token，过期时间 2 小时 |
| 数据传输 | 全链路 HTTPS | TLS 1.3 |
| 敏感信息 | 手机号脱敏展示 | 138****8000 |
| 防刷限流 | 单用户 100 次/分钟 | Redis + 滑动窗口算法 |
| 支付安全 | 金额回调签名验证 | RSA + MD5 签名 |

### 7.3 兼容性要求

| 平台 | 最低版本 |
|------|---------|
| 微信小程序 | 基础库 2.10.0+ |
| iOS App | iOS 14+ |
| Android App | Android 8.0+ |
| Web 管理后台 | Chrome 90+, Edge 90+, Safari 15+ |
