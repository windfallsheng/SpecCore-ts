# 通用业务规则（全端共享）

> 本文件为示例模板。实际使用时，将内容复制到 `.speccore/GLOBAL/BUSINESS_RULES/01-common.md`
> 文件名包含 `-common` 的会被所有端自动加载（最多 4000 字符/文件）
>
> ⚠️ **命名警告**：端级规则文件名必须与 CONSTITUTION.md / PROJECT.yaml 中的工程标识完全一致

## 1. 角色体系与权限矩阵

### 1.1 角色定义

| 角色标识 | 角色名称 | 权限级别 | 数据范围 | 说明 |
|:---|:---|:---|:---|:---|
| `SUPER_ADMIN` | 超级管理员 | L5 | 全部 | 系统初始化角色，不可删除 |
| `ADMIN` | 管理员 | L4 | 本组织全部 | 可管理用户、配置系统参数 |
| `OPERATOR` | 运营人员 | L3 | 本组织业务数据 | 可操作订单、商品、内容 |
| `USER` | 普通用户 | L1 | 仅自己的数据 | 浏览、下单、查看个人记录 |

### 1.2 权限矩阵

| 功能模块 | SUPER_ADMIN | ADMIN | OPERATOR | USER |
|:---|:---:|:---:|:---:|:---:|
| 用户管理 | CRUD | R | - | - |
| 订单管理 | CRUD | CRUD | CRUD | R（自己的） |
| 商品管理 | CRUD | CRUD | CRU | R |
| 系统配置 | CRUD | RU | - | - |

> **规则：** 所有写操作必须记录操作人 ID + 操作时间 + IP 地址

## 2. 通用状态机

### 2.1 订单状态机

```
[待支付] --支付成功--> [已支付] --发货--> [已发货] --签收--> [已完成]
    |                      |                    |
    |--超时/取消            |--退款申请           |--拒收
    v                      v                    v
 [已取消]              [退款中] --> [已退款]   [退货中] --> [已退货]
```

**状态流转规则：**
- 订单创建后 30 分钟未支付自动取消
- 已支付订单 7 天内可申请退款
- 所有状态变更必须记录状态变更日志

## 3. 通用业务规则

### 3.1 金额计算规则

- 所有金额字段统一使用**分**存储（整数），禁止用 float/double
- 前端展示时转换为元，保留 2 位小数
- 中间计算使用 `BigDecimal` 或 `decimal.js`，最终四舍五入到分

### 3.2 时间规则

- 统一使用 UTC 时间存储，格式 `YYYY-MM-DDTHH:mm:ssZ`
- 根据用户时区转换后展示
- 超时计算使用创建时间 + 固定时长

### 3.3 删除规则

- **所有删除必须为软删除**，保留 `deleted_at` 和 `deleted_by` 字段
- 软删除数据默认不查询，需显式加 `includeDeleted=true`

### 3.4 分页规则

- 默认 `page = 1`，`pageSize = 20`
- 最大 `pageSize = 100`
- 默认按创建时间倒序

## 4. 通用错误码

| 错误码 | HTTP 状态 | 说明 |
|:---|:---:|:---|
| `BIZ_001` | 400 | 参数校验失败 |
| `BIZ_002` | 404 | 资源不存在 |
| `BIZ_003` | 409 | 资源冲突（重复提交） |
| `BIZ_004` | 403 | 无权限 |
| `BIZ_005` | 422 | 业务规则冲突（状态不允许） |

## 5. 数据库表必备字段

| 字段名 | 类型 | 说明 |
|:---|:---|:---|
| `id` | BIGINT | 主键（自增或雪花 ID） |
| `created_at` | DATETIME | 创建时间（不可修改） |

| `created_by` | BIGINT | 创建人 ID |
| `updated_by` | BIGINT | 更新人 ID |
| `deleted_at` | DATETIME | 软删除时间 |
| `version` | INT | 乐观锁版本号 |

## 6. 约束与禁忌

- ❌ **禁止**在代码中硬编码业务参数，必须走配置中心
- ❌ **禁止**直接物理删除生产数据
- ❌ **禁止**在日志中打印密码、Token、身份证号等敏感信息
- ❌ **禁止**跨服务直接访问数据库，必须通过 API 调用
- ❌ **禁止**在循环中调用外部接口，必须批量处理或使用消息队列

## 7. 扩展规则（按需补充）

> 以下规则根据实际项目类型选择性补充。

### 7.1 行业特有规则

**电商场景：**
- 库存扣减策略：下单扣减 vs 支付扣减（推荐支付扣减 + 预占机制）
- 秒杀场景：库存预热到 Redis，使用 Lua 脚本原子扣减
- 优惠券：过期自动失效，退款时按比例退还

**医疗场景：**
- 数据隐私等级：公开 / 内部 / 机密 / 绝密
- 患者数据访问必须记录审计日志，保留 10 年
- 诊断结果修改需双人复核

**金融场景：**
- 交易流水不可修改，错误交易用冲正单处理
- 日终对账：系统流水 vs 银行流水，差异自动告警
- 敏感操作需短信/邮件二次确认

### 7.2 第三方接口约束

| 接口类型 | 限制 | 应对策略 |
|:---|:---|:---|
| 支付渠道 | 单笔/单日限额 | 超限自动拆单或拒绝 |
| 短信服务 | 5 条/分钟/手机号 | 频控 + 图形验证码 |
| 邮件服务 | 100 封/小时 | 队列削峰，超量延迟发送 |
| 地图服务 | 5000 次/天 | 本地缓存 + 降级策略 |
| OCR 识别 | 10 次/分钟 | 异步队列，结果回调 |

### 7.3 数据归档策略

| 数据类型 | 在线保留 | 归档方式 | 归档后保留 |
|:---|:---|:---|:---|
| 订单数据 | 3 年 | 按年分表，冷数据迁移 | 7 年 |
| 操作日志 | 90 天 | 超过后迁移到归档库 | 1 年 |
| 系统日志 | 30 天 | ELK 过期自动清理 | 30 天 |
| 审计日志 | 在线 | 单独存储，不可删除 | 永久 |
| 文件附件 | 在线 | 超过 1 年迁移到冷存储（OSS 低频/归档） | 按业务定 |

### 7.4 多租户规则

- **数据隔离：** 每个租户独立 Schema 或独立数据库（推荐独立 Schema）
- **资源配额：**
  - 免费版：10 用户 / 100GB 存储 / 1000 次 API/天
  - 专业版：100 用户 / 1TB 存储 / 10000 次 API/天
  - 企业版：无限制
- **租户隔离校验：** 每次数据操作必须校验当前用户所属租户，禁止跨租户访问
- **租户数据导出：** 支持租户一键导出全部数据（GDPR 要求）

### 7.5 合规要求

**等保 2.0（国内）：**
- 三级等保：必须过测评，每年复评
- 关键要求：访问控制、安全审计、数据完整性、数据保密性

**GDPR（欧盟）：**
- 用户有权查看、修改、删除自己的全部数据
- 数据泄露 72 小时内上报监管机构
- 默认隐私设计，最小化数据收集

**PCI-DSS（支付卡行业）：**
- 卡号加密存储，禁止明文保存 CVV
- 支付环境网络隔离
- 每年第三方安全评估

**个人信息保护法（国内）：**
- 收集个人信息需明确告知用途
- 用户同意后可撤回
- 跨境数据传输需安全评估
