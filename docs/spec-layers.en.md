# Spec Multi-Layer Loading Mechanism

> Applicable: v8.3.x+

> 💡 **Command types**: `speccore execute` below is a 🔒 AI command — use `@spec-ask` in an AI IDE. See [Quick Start](quick-start.en.md).

## Multi-Layer Spec Architecture

SpecCore's Spec files are organized into layers: **global knowledge base** (auto-generated by `analyze --full`), **global constraints** (configured at `init`), **iteration context** (iteration-level docs), **Task execution** (task-level input).

```
Layer 0 — Global knowledge base (analyze --full auto-gen + smart injection)
  🤖 GLOBAL/platforms/{platform}/ → Phase 1 per-platform analysis
  🤖 GLOBAL/synthesis/            → Phase 2 cross-platform synthesis
  🤖 GLOBAL/INDEX.md              → lightweight index after Phase 2
  ✅ split/execute/analyze        → required-read injection + TOC, AI self-Read

Layer 1 — Global constraints (execute auto-parses)
  ✅ CONSTITUTION.md  spec-rule block → code conventions auto-applied
  ✅ TECH_STACK.md    tech-stack block → tech stack auto-detected

Layer 2 — Iteration context (human docs, manual lookup)
  📖 010-requirements/  current iteration requirements
  📖 020-specs/         architecture decisions, tech analysis

Layer 3 — Task execution (execute core input)
  ✅ Task/REQ.md   requirements (API table parsed ✓)
  ✅ Task/TECH.md  tech plan
  ✅ Task/TASK.md  task breakdown (status updated ✓)
```

## 1. Layer 0: Global Knowledge Base (auto-gen + smart injection)

### Three-phase auto pipeline

```
Phase 1: per-platform analysis
  CLI reads source → AI generates specialized analysis → GLOBAL/platforms/{platform}/
  Platform types auto-detected: backend / web admin / mobile H5 / mini-program / native app
  Common 10 dimensions + platform-specific dimensions

Phase 2: cross-platform synthesis
  CLI reads Phase 1 → AI generates three synthesis docs → GLOBAL/synthesis/
  - CROSS_PLATFORM.md — cross-platform business relationship graph
  - ARCHITECTURE.md  — full architecture + ADR + security architecture
  - TECH_FULL.md     — full tech plan + capacity planning
  Then auto-generates GLOBAL/INDEX.md lightweight index

Phase 3: feature-unit synthesis
  CLI reads Phase 2 → AI splits by feature unit → iteration-level 010-requirements/
  Each unit: user stories + per-platform requirements + API summary + data dictionary + test points
```

### Smart context injection (core mechanism)

**Design: CLI gives a map + marks required reads; AI decides which files to Read.**

TOC covers 6 sources:

| Group | Source | Purpose | When AI references |
|:---|:---|:---|:---|
| 📚 Cross-platform | GLOBAL/synthesis/ | architecture, tech plan | execute generating code |
| 📱 Per-platform | GLOBAL/platforms/ | per-platform analysis | execute on a specific platform |
| 🏗 Project-level | GLOBAL/PROJECTS/ | per-project analysis | execute on a specific project |
| 📖 Reference | GLOBAL/*.md | glossary, code index, tech stack | any command needing context |
| ✏️ Templates | PATTERNS/TEMPLATES/ | Spec writing templates | analyze writing Specs |
| 📏 Rules | RULES/ | code review, completion checks | execute/done |

```
analyze --full Phase 2 done
├── writes GLOBAL/synthesis/ (CROSS_PLATFORM + ARCHITECTURE + TECH_FULL)
├── writes GLOBAL/platforms/{platform}/
├── auto-generates GLOBAL/INDEX.md
│
├──→ split prompt injection:
│    ├── 📌 required: INDEX.md full text (≤1500 chars)
│    └── 📂 optional: TOC (path + description + ## headings)
│
├──→ execute prompt injection:
│    ├── 📌 required: INDEX.md full text
│    ├── 📂 optional: TOC (synthesis + per-platform)
│    └── 💡 current platform marked ⬅, AI self-Reads needed files
│
└──→ analyze prompt injection:
     ├── 📌 required: INDEX.md full text
     └── 📂 optional: TOC
```

### What AI sees in the prompt

```markdown
## 🌐 Global Knowledge Base
> Required reads injected; Read other files on demand.

### 📌 Required (injected)
(INDEX.md full text — project list, per-platform doc list, synthesis doc list)

### 📂 Optional (Read on demand)
> Current task involves **admin** platform, prefer its docs

**Global synthesis docs** (.speccore/GLOBAL/)
- `synthesis/ARCHITECTURE.md` — full system architecture
  Sections: overview | service dependencies | tech stack | deploy architecture | ADR | security
- `synthesis/TECH_FULL.md` — full tech plan
  Sections: common modules | API versioning | data consistency | perf optimization

**Per-platform docs** (.speccore/GLOBAL/)
📂 admin/ ⬅ current platform
  - `platforms/admin/ANALYSIS.md` — admin — ANALYSIS
    Sections: features | interfaces | data model | business rules | security
📂 h5/
  - `platforms/h5/ANALYSIS.md` — h5 — ANALYSIS
    Sections: features | interfaces | adaptation | first-screen perf
```

### Implementation details

| Function | Location | Purpose |
| :--- | :--- | :--- |
| `buildGlobalTOC()` | prompt-builder.ts | Scan 6 sources, extract `##` headings |
| `loadGlobalContext()` | prompt-builder.ts | Inject INDEX.md + TOC |
| `generateGlobalIndex()` | synthesize.ts | Auto-gen INDEX.md after Phase 2 |
| `formatGlobalContext()` | prompt-builder.ts | Format grouped Markdown (shared) |

**Key design decisions:**
- No prefetch, only TOC — AI decides what to read
- Only read `##` headings — fast TOC generation
- Filter timestamp backups — `isTimestampBackup()` excludes `.bak`
- Current-platform marker — guides AI to prefer current platform docs
- 6 sources covered — synthesis/platforms/PROJECTS/flat/PATTERNS/RULES

## 2. Layer 1: Global Constraints (auto-parsed)

### CONSTITUTION.md → spec-rule injection

Rules marked with `<!-- spec-rule: xxx -->` are auto-injected into generated code during `speccore execute`:

```markdown
<!-- spec-rule: exception-handler -->
- Unified exceptions: all Controllers throw BusinessException
- Global handling: @ControllerAdvice
<!-- speccore rule -->
```

Five supported rule types:

| Rule | Effect | Code change |
| :--- | :--- | :--- |
| `exception-handler` | Exception handling | `return ok()` → `throw new BusinessException()` |
| `response-format` | Return format | `ResponseEntity<?>` → `Result<T>` |
| `orm` | ORM framework | JPA → MyBatis-Plus templates |
| `validation` | Param validation | auto-import `@Valid` / `javax.validation.*` |
| `naming` | Naming convention | Controller → XxxController |

**Change CONSTITUTION once, all subsequent `execute` takes effect.**

### TECH_STACK.md → tech stack detection

Marked with `<!-- tech-stack: backend -->` and `<!-- tech-stack: frontend -->`, execute auto-detects language/framework:

```markdown
<!-- tech-stack: backend -->
- Language: Go 1.21
- Framework: Gin
- ORM: GORM
<!-- /tech-stack -->
```

```bash
speccore execute --task=Task-001 --force
# → Tech Stack: Gin + React
```

Supported languages: Java / TypeScript / Go / Python

## 3. Layer 2: Iteration Context (human docs)

These files don't drive code generation but provide key project info:

| File | Purpose | Who reads |
| :--- | :--- | :--- |
| `010-requirements/REQUIREMENT.md` | Iteration requirements, priorities, milestones | PM, developers |
| `020-specs/ANALYSIS.md` | Requirement analysis | Developers |
| `020-specs/TECH.md` | Tech plan | Developers |

## 4. Layer 3: Task Execution (core input)

```
Task-001-order-management/
├── _shared/
│   └── API_CONTRACT.yaml     → API contract
├── 00-specs/
│   ├── REQ.md                → requirements
│   ├── TECH.md               → tech plan
│   ├── CONTEXT.md            → task context
│   └── TASK.md               → task breakdown
├── booking-service/         → backend service platform
│   └── order-api/           → subtask (TASK.md; code goes to source path)
└── h5-mobile/               → mobile H5 platform
    └── order-page/          → subtask (TASK.md)
```

**execute workflow:**

1. Load CONSTITUTION.md → extract spec-rule rules
2. Load TECH_STACK.md → detect language/framework
3. Read 00-specs/REQ.md → parse API table
4. Generate code to subtask dir from REQ.md + rules + tech stack

## 6. Complete Workflow

### 💬 Conversational (recommended for new users)

```
1. "My Java project uses Spring Boot + JPA, unified exceptions via ApiException"
   → AI creates CONSTITUTION.md spec-rule + TECH_STACK.md

2. "Create Q3 iteration"
   → AI runs speccore iteration create --name=Q3

3. "Create an order-management feature task"
   → AI runs speccore task new --name="order-management"

4. "Task-001 needs CRUD with pagination and soft delete"
   → AI fills REQ.md API table

5. "Develop Task-001"
   → AI runs speccore execute --task=Task-001 --force
```

### ⌨️ Command line

```bash
# 1. Configure global rules (once)
vim .speccore/CONSTITUTION.md
vim .speccore/GLOBAL/TECH_STACK.md

# 2. Create iteration and tasks
speccore iteration create --name=Q3
speccore task new --name="order-management" --platforms=web,backend

# 3. Write requirements
vim Iteration-Q3/Task-001-order-management/backend/REQ.md

# 4. Execute (rules + tech stack auto-injected)
speccore execute --task=Task-001 --force
```

## 7. Backup & Rollback

AI auto-creates `.bak` before modifying any Spec file:

```bash
# Conversational rollback
"The last change to Task-001 is wrong, roll it back"  → AI restores from .bak
```

Backups live in the same dir (e.g. `REQ.md.bak`), cleaned after restore, expire in 24h.
