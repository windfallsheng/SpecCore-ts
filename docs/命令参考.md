## 💡 两种使用方式

同一个功能在终端 CLI 和 AI 对话框中有不同写法。以下按三类说明。

### 📋 通用命令（两种场景都能用）

| 功能 | 🖥 终端 CLI | 💬 AI 对话 | 说明 |
|:---|:---|:---|:---|
| 初始化 | `speccore init` | `/spec-init` | — |
| 导入需求 | `speccore doc2spec -f PRD.docx -p backend --iter=Q1` | `/spec-doc2spec PRD.docx` | CLI 用 `-f` 传文件路径 |
| 拆分任务 | `speccore iteration split -i Q1` | `/spec-split Q1` | CLI 用 `-i` 指定期次 |
| 执行开发 | `speccore execute -t Task-001 --force` | `/spec-execute Task-001` | CLI 用 `-t` 指定 Task |
| 提交 PR | `speccore pr --task=Task-001` | `/spec-pr Task-001` | — |
| 归档完成 | `speccore done --task=Task-001` 或 `done --all` | `/spec-done Task-001` | 单任务/批量/自动扫描 |
| 查看状态 | `speccore status-panel` | `/spec-status-panel` | — |
| 需求变更 | `speccore change "描述" -t Task-001` | `/spec-change Task-001` 或直接说人话 | — |
| Bug 修复 | `speccore task new -n "名称" -d "描述" --type=bugfix` | `/spec-bugfix` 或直接说人话 | — |
| 需求分析 | `speccore analyze -I Q1` | `/spec-analyze Q1` | CLI 支持代码分析、多目录、范围选择 |
| 执行计划 | `speccore plan -i Q1` | `/spec-plan Q1` | 创建计划、查看历史、与 execute/schedule 联动 |
| 创建 Task | `speccore task new -n 名称` | `/spec-task-new` | — |
| 合规检查 | `speccore validate -i Q1` | `/spec-validate Q1` | — |
| 智能入口 | `speccore ask "查询"` | 直接说人话 | CLI 中也可省略 `ask`，直接 `speccore "说人话"` |
| 智能级联 | `speccore dev` | `/spec-dev` | — |
| 操作历史 | `speccore ops` | `/spec-ops` | — |
| 重命名 | `speccore rename --task=Task-001 --name=新名` | `/spec-rename` | — |

### 🖥 CLI 专有（复杂参数，更适合终端）

| 命令 | 用法 | 原因 |
|:---|:---|:---|
| `execute --verify` | `speccore execute -t Task-001 --force --verify` | 需要 `--verify` 等组合参数 |
| `status-panel --export` | `speccore status-panel --export=html --assignee=张三` | 导出/筛选高级参数 |
| `dev --auto` | `speccore dev --auto --from=split` | 全自动流水线 |
| `task new --batch-file --type=bugfix` | `speccore task new --batch-file=bugs.xlsx --type=bugfix --schedule=night` | 批量 Bug + 调度 |

### 💬 AI 对话专有（需要 AI 理解上下文）

| 方式 | 示例 | 原因 |
|:---|:---|:---|
| 直接说人话 | "帮我创建用户登录功能" "看一下项目进度" | 自然语言，AI 自动匹配命令 |
| AI 深度分析 | `/spec-analyze Q1` → AI 通读代码填充 Spec | 需要 AI 上下文理解 |
| AI 反工程 | `/spec-import-analyze` → AI 从源码倒推需求 | 纯 AI 行为 |

> **为什么有这些区别？** CLI 擅长精确控制和脚本化，需要明确的参数名。AI 对话擅长理解自然语言和项目上下文，可以直接说人话。复杂参数（如文件路径、筛选条件）在 CLI 中更方便；需要 AI 理解的项目分析在对话中更自然。

### 📋 plan — 执行计划

```bash
# 创建计划（依赖排序 + 团队分配）
speccore plan -I Q1                              # 自动生成
speccore plan -I Q1 --type=bugfix --priority=high  # 筛选条件
speccore plan -I Q1 -a 张三,李四                 # 指定人员

# 交互模式：预览 → 调整 → 确认
speccore plan -I Q1 --interactive
speccore plan -I Q1 --dry-run                    # 只看不保存

# 历史管理
speccore plan --list                             # 查看历史（显示🙋手动/🤖自动/⏰调度）
speccore plan --show plan-xxx                    # 查看详情（任务列表/分批/筛选）
speccore plan --delete plan-xxx                  # 删除

# 与 execute/schedule 联动
speccore execute --plan=plan-xxx                 # 按历史计划执行
speccore schedule create --at "02:00" --plan=xxx # 定时按计划执行
```

> `execute --all` 每次自动保存计划（source=auto），`plan --list` 可查。

### 🚀 dev — 智能级联 + 全自动流水线

```bash
# 检测当前阶段，引导下一步
speccore dev                                     # 智能引导

# 全自动流水线
speccore dev --auto                              # init → done 全自动
speccore dev --auto --from=analyze               # 从 analyze 开始
speccore dev --auto --from=split --to=execute    # 只跑 split→plan→execute

# 快速引导执行下一步
speccore dev --force                             # 自动执行检测到的下一步
```

### ✅ done — 收尾归档

三种粒度，统一流程：校验 → 归档 → 同步到全局层 → 审计。

```bash
# 单任务
speccore done --task=Task-001
speccore done --task=Task-001 --interactive          # 预览步骤，可跳过校验/同步

# 批量指定
speccore done --task=Task-001,Task-002,Task-003

# 自动扫描 + 交互确认
speccore done --all -I Q1                         # 自动找已完成任务
speccore done --all -I Q1 --interactive            # 预览列表 → 确认 → 批量执行
```

> `--all` 扫描期次下所有 Task，`--interactive` 预览后确认。每步自动校验→归档→同步→审计。

## 🔬 分析审计

| 命令 | 别名 | 功能 | 参数 |
| :--- | :--- | :--- | :--- |
| `speccore analyze` | `al` | AI 增强分析引擎：需求+代码+AI上下文 | `-I, --iteration <name>` `-t, --task <id>` `--scope <global\|iteration\|task>` `--src <dirs>` `--req <files>` `-o, --output <file>` `--depth <quick\|normal\|deep>` `--auto` `--interactive` |
| `speccore impact` | — | 变更影响分析 | `--req <id>` `--task <id>` |
| `speccore baseline` | — | 版本基线管理 | `--name <name>` `--compare <name>` `--restore <name>` `--req <id>` |
| `speccore audit` | — | AI 智能审计 | `--fix` |

```bash
# 🤖 AI 增强分析引擎 — 三种范围
# 默认从 期次-XX/00-产品需求/ 读取产品原始需求
# 输出 Spec 文档到 期次-XX/00-需求文档/
speccore analyze --scope global --depth deep              # 全局代码健康+架构审查
speccore analyze --scope global --src backend,frontend    # 多目录源码分析(显式指定 --src)
speccore analyze --scope global --req docs/req.md         # 跨期次需求一致性(纯需求,不扫描源码)
speccore analyze -I Q1                                    # 期次需求分析(默认,读 00-产品需求/)
speccore analyze -I Q1 --src backend/src                  # 期次需求+代码联合(显式 --src)
speccore analyze --scope task -t Task-01 -I Q1            # 任务分析+文档补全
speccore analyze --interactive -I Q1                      # 交互问答模式

# 📊 多目录多文档
speccore analyze --src backend/src,frontend/src --req docs/login.md,docs/pay.md --scope global

# 🤖 AI 上下文: 分析后生成 .speccore/prompts/analyze-*.md
#    由 WorkBuddy 等 AI 助手读取进行智能分析,支持反复迭代
# 
# 输出目录结构:
#   期次-Q1/
#     ├── 00-产品需求/          ← 产品原始需求（只读，导入后不动）
#     └── 00-需求文档/          ← Spec 规范文档（analyze 生成）
#           ├── ANALYSIS.md     ← AI 分析报告
#           ├── TECH.md         ← 技术方案模板
#           ├── TEST.md         ← 测试计划模板
#           ├── REVIEW.md       ← Code Review 清单
#           ├── RISK.md         ← 风险评估
#           ├── DEPS.md         ← 依赖清单
#           └── MONITOR.md      ← 监控指标

speccore impact --req=REQ-001
speccore baseline --name=v1.0
speccore baseline --compare=v1.0 --name=v1.1
speccore audit --fix
```
