# SpecCore 总览

## 一、命令全景

### 🔵 日常 7 步流

```
init         项目初始化
doc2spec    需求文档导入 (Word/MD → Spec)
analyze      需求分析 + 源码对标 + 架构影响
split        拆分任务 (11份文档 + IMPACT)
execute      执行开发 (模板生成代码)
pr           自动创建 Pull Request
done         一键收尾 (validate→archive→sync)
```

### 🟡 偶尔用 (16)

```
lifecycle    任务状态机 (dev→test→review→done)
rollback     回滚任务 + 删除分支 + 归档
merge-check  合并冲突预测
tracker      全量需求变更追踪
ops          操作历史查看
new-task     新建任务
bugfix       创建 Bug 修复任务
change       需求变更联动
spec         自然语言智能入口
arch-update  架构文档自动更新
validate     Spec 一致性校验
dev          智能引导 (检测阶段)
open          打开任务文件
status-panel  IDE 状态面板
constitution  宪法自动检测
status       任务状态查看
context      输出任务上下文 (给 AI 粘贴)
```

### ⚪ 全局层 (5)

```
sync             期次 ↔ 全局双向同步
sync-global      同步到全局层
global-status    全局层状态
iteration-from-global  从全局层生成期次
import           导入代码到全局层
```

### ⚪ 查看类 (8)


### ⚪ 特殊场景 (6)


### ⚪ 工具类 (6)


## 三、Spec → Code 理念

```
  "Code by Spec, Not by Vibe"

  ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
  │  📝 Spec  │ → │  🔍 分析  │ → │  📦 任务  │ → │  💻 代码  │
  │ 需求规格  │    │ 对标源码  │    │ 11份文档  │    │ 模板生成  │
  └──────────┘    └──────────┘    └──────────┘    └──────────┘
       ↑                                               │
       │              📜 CONSTITUTION                  │
       │          (强制规则 + 质量关卡)                  │
       └────────────────── 验证 ───────────────────────┘

  每个阶段都需用户确认（[y]保存 / [N]取消）
  分析 → 确认 → 拆分 → 确认 → 执行 → 关卡 → 完成
```

## 五、质量关卡

```
  in_progress ──→ testing ──→ review ──→ done
       │              │           │
       │         TEST.md      REVIEW.md
       │         完成？        审批？
       │              │           │
       └──── 关卡 ────┴─── 关卡 ──┘

  🚫 跳过 testing → review: 阻止
  🚫 跳过 review → done:    阻止
  ⚠️ TEST.md 未完成 → review: 阻止
  ⚠️ REVIEW.md 未审批 → done: 阻止
```

## 六、注解标记

```
  开发者只需在代码中加一行注释，analyze 自动精准读取：

  // @spec-module 订单管理    → 定义模块边界
  // @spec-api POST /api/xxx  → 标记接口归属
  // @spec-entity Order        → 标记数据实体
  // @spec-dependency 用户模块 → 声明模块依赖
```
