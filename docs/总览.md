# SpecCore 总览

## 一、命令全景

### 🔵 核心流程

```
init         项目初始化
doc2spec    需求文档导入 (Word/MD → Spec)
analyze      统一分析引擎（需求+代码，全局/期次/任务三级输出）
split        拆分任务 (11份文档 + IMPACT)
execute      执行开发 (模板生成代码)
pr           自动创建 Pull Request
done         一键收尾 (validate→sync)
```

### 🟡 偶尔用 (16)

```
lifecycle    任务状态机 (dev→test→review→done)
rollback     回滚任务 + 删除分支 + 归档
merge-check  合并冲突预测
tracker      全量需求变更追踪
ops          操作历史查看
task new     创建任务 (--type=feature|bugfix)
change       需求变更联动
arch-update  架构文档自动更新
validate     Spec 一致性校验
dev          智能级联（自动检测→执行下一步）
status-panel  IDE 状态面板
constitution  宪法自动检测
status       任务状态查看
context      输出任务上下文 (给 AI 粘贴)
schedule     调度执行 (create/list/detail/cancel/daemon)
ask          智能入口（自然语言意图识别）
```

### ⚪ 全局层 (3)

```
sync             双向同步 (--global 同步到全局层)
global-status    全局层状态
iteration-from-global  从全局层生成期次
```

### ⚪ 查看类 (4)

```
health       项目健康检查
trace        追溯需求 → 代码
diff         差异对比
search       搜索
```

### ⚪ 管理类 (5)

```
audit        智能审计
baseline     版本基线
config       配置管理
delete       删除清理
update       更新
```

### ⚪ 特殊场景 (2)

```
plan         执行计划
handover     交接文档
```

### ⚪ 工具类 (3)

```
welcome      欢迎面板
help         帮助
completion   命令补全
```

### ⚪ 期次/任务子命令 (7)

```
iteration create  创建期次
iteration split   拆分任务 (同 split)
task new          新建任务
rollback          回滚 (同 rollback)
validate          校验 (同 validate)
watch             文件监控
constitution      自动检测技术栈 + 生成宪法
```

> 💡 v5.22.x | 共 **45 个命令**。直接输入 `speccore` 看自适应引导面板。

## 三、Spec → Code 理念

```
  "Code by Spec, Not by Vibe"

  ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
  │  📝 Spec  │ → │  🔍 分析  │ → │  📦 任务  │ → │  💻 代码  │
  │ 需求规格  │    │ 对标源码  │    │ 11份文档  │    │ 模板生成  │
  └──────────┘    └──────────┘    └──────────┘    └──────────┘
       ↑                                               │
       │              📜 CONSTITUTION                  │
       │          (强制规则 + 质量关卡)                  │
       └────────────────── 验证 ───────────────────────┘

  每个阶段都需用户确认（[y]保存 / [N]取消）
  分析 → 确认 → 拆分 → 确认 → 执行 → 关卡 → 完成
```

```
  Task-001-订单管理/
  ├── backend/

  │   ├── TECH.md         🔧 技术方案

  │   ├── TEST.md         🧪 测试用例
  │   ├── REVIEW.md       ✅ 审查清单
  │   ├── SCHEMA.md       🗄️ 数据库DDL (DB任务)

  │   ├── ERROR_CODES.md  ❌ 错误码
  │   └── ADR.md          📐 架构决策 (技术任务)

  └── .risk               ⚠️ 风险评分
```

## 五、质量关卡

```
  in_progress ──→ testing ──→ review ──→ done
       │              │           │
       │         TEST.md      REVIEW.md
       │         完成？        审批？
       │              │           │
       └──── 关卡 ────┴─── 关卡 ──┘

  🚫 跳过 testing → review: 阻止
  🚫 跳过 review → done:    阻止
  ⚠️ TEST.md 未完成 → review: 阻止
  ⚠️ REVIEW.md 未审批 → done: 阻止
```

## 六、注解标记

```
  开发者只需在代码中加一行注释，analyze 代码分析自动精准读取：

  // @spec-module 订单管理    → 定义模块边界
  // @spec-api POST /api/xxx  → 标记接口归属
  // @spec-entity Order        → 标记数据实体
  // @spec-dependency 用户模块 → 声明模块依赖

  CLI 用法：
  speccore analyze --scope global          → 全局代码健康报告
  speccore analyze --src backend,frontend   → 多目录代码分析
  speccore analyze -I Q1 --src backend      → 期次需求+代码联合分析
```
