## 快速上手：简洁模式全流程（推荐）

从零开始的完整开发闭环。所有命令均为简洁模式（17 个核心命令）。

### 一、初始化项目

```bash
speccore init                          # 默认简洁模式
# 生成: .speccore/ + 17 个 Slash Command
# 生成: CAPABILITIES.md（项目能力注册表）
```

### 二、导入需求

```bash
# 从 Word/PDF/MD 文档导入
speccore doc2spec --file=PRD.docx --platform=backend -I Q1
```

### 三、需求分析 — 三种粒度

```bash
# 方式 1: 期次分析（需求完整性+代码对标+架构影响）
speccore analyze -I Q1
# 产出: 00-需求文档/ANALYSIS.md + 完整性检查 + 架构影响评估

# 方式 2: 代码分析（多目录+全局报告）
speccore analyze --scope global --src backend,frontend --depth deep
# 产出: .speccore/GLOBAL/CODE_HEALTH.md + 复杂度热点 + API清单 + 依赖分析

# 方式 3: 任务级分析
speccore analyze --scope task -t Task-01 -I Q1
# 产出: 填充 TECH.md + TEST.md + REVIEW.md + 补齐缺失文件
```

### 四、拆分任务 — 三种方式

```bash
# 方式 1: 自动拆分（默认）
speccore iteration split -I Q1

# 方式 2: 交互拆分（预览+逐一确认）
speccore iteration split -I Q1 --interactive

# 方式 3: 手动创建
speccore task new --name=用户登录 --type=feature
```

### 五、执行计划

```bash
speccore plan -I Q1             # 自动模式
speccore plan -I Q1 --interactive  # 交互确认
```

### 六、执行开发 — 六种模式

```bash
# 模式 1: 预览（默认）
speccore execute -t Task-001          # 展示执行计划，不实际执行

# 模式 2: 直接执行
speccore execute -t Task-001 --force  # 跳过预览，直接开发

# 模式 3: 验证闭环
speccore execute -t Task-001 --force --verify
# 生成代码 → 自动检查 TEST/REVIEW/DEPLOY → 不通过则修复 → 最多 3 轮

# 模式 4: 交互模式
speccore execute -t Task-001 --interactive  # 选择要执行的任务

# 模式 5: 预览模式
speccore execute -t Task-001 --dry-run  # 只预览，不执行

# 模式 6: 严格模式
speccore execute -t Task-001 --strict   # 前置检查 req/tech/test 后才生成代码

# 夜间调度
speccore execute --all --scheduled          # 只执行标记为队列的任务
```

### 七、提交 PR — 两种方式

```bash
# 自动模式
speccore pr --task=Task-001               # 推送 + 创建 PR

# 交互模式（分步）
speccore pr --task=Task-001 --interactive
# ① git status 预览变更 ② [a]全部 [p]挑选 add
# ③ commit ④ 确认推送 ⑤ 确认创建 PR
```

### 八、完成任务

```bash
speccore done --task=Task-001
# validate → sync-global → 自进化规则检测
```

### 九、额外操作

```bash
# 需求变更
speccore change "把手机号改成国际格式" -t Task-001
speccore change -t Task-001 --interactive   # 交互确认

# Bug 批量处理
speccore task new --batch-file=bugs.xlsx --type=bugfix --schedule=night --interactive
# 预览 → 编辑/跳过 → 确认创建 → 标记夜间执行

# 检查合规
speccore validate -I Q1

# 操作历史
speccore ops

# 可视化看板
speccore status-panel
```

### 完整闭环总结

```
speccore init                    ① 初始化
speccore doc2spec                ② 导入需求文档
speccore analyze                 ③ 分析（需求+代码）
speccore iteration split         ④ 拆分 Task
speccore plan                    ⑤ 执行计划
speccore execute --force         ⑥ AI 开发
speccore pr                      ⑦ 提 PR
speccore done                    ⑧ 完成归档

---

```
传统模式:  需求变更 → 直接改代码 → 文档滞后 → 知识丢失
SpecCore:     需求变更 → 先更新 Spec → 记录变更履历 → 再改代码
```

> ⌨️ `speccore xxx` = 终端 | 🤖 `/spec-xxx` = AI Slash | 💬 `"xxx"` = 对 AI 说话（三种入口，效果相同）

## 场景二：需求文档导入

**背景**: PM 给了需求文档，有 Word 格式也有 Markdown 格式，不同端在不同文档中。

### 方式一：Word 文档转换导入

```bash
# 单文件导入
speccore doc2spec -f 后台PRD.docx --iter=Q3 -p 后台管理端
# 💬 "把 Q3 的后台需求 Word 转成 Spec"

# 批量导入（推荐）—— 一次命令，全部搞定
speccore doc2spec --files \
  "后台PRD.docx=后台管理端,后台H5接口.docx=后台H5端,Web需求.docx=Web,H5需求.docx=H5" \
  -i Q3
```

### 方式二：Markdown 文档直接导入

```bash
# .md 文件直接导入，无需 pandoc
speccore doc2spec --files \
  "后台接口.md=后台管理端,前端页面.md=Web,小程序页面.md=H5" \
  -i Q3

# Word 和 MD 可以混着导入
speccore doc2spec --files \
  "后台PRD.docx=后台管理端,前端页面.md=Web" \
  -i Q3
```

### 导入后的文件结构

| 文件 | 类型 | 说明 |
| :--- | :--- | :--- |
| `{端名}需求.md` | 手动维护 | 各端独立的需求文档 |
| `REQUIREMENT.md` | **自动生成** | 各端汇总，供 `iteration split` 使用 |
| `INDEX.md` | **自动生成** | 端列表索引，供 `split` 智能端检测 |
| `images/` | **自动生成** | Word 中提取的图片 |

### 需求变更时该改哪个？

| 变更来源 | 操作 |
| :--- | :--- |
| PM 给了新版本 Word | 重新执行 `doc2spec --files`（自动覆盖 `{端}需求.md` + 刷新 `REQUIREMENT.md`） |
| 开发中微调需求 | 用 `speccore change -t Task-001 --desc="xxx"`（不要手动改 REQUIREMENT.md） |
| 需要调整分端结构 | 改 `{端名}需求.md`，然后重新 `doc2spec` |
| 全量层同步 | `REQUIREMENT.md` → `speccore sync-global --direction=to_global` |

> ⚠️ `REQUIREMENT.md` 和 `INDEX.md` 是衍生文件，下次 `doc2spec` 会覆盖。**不要手动编辑这两个文件。**

**验证**:
```bash
ls 期次-Q3/00-需求文档/
# → 后台管理端需求.md 后台H5端需求.md  Web需求.md  H5需求.md  REQUIREMENT.md  INDEX.md  images/
```

## 场景五：定时调度执行

### 基础执行

```bash
speccore execute -t Task-001 --force              # 单任务
speccore execute --all --batch-size=3              # 按依赖排序，每批 3 个
speccore execute --all --resume                    # 断点续传
speccore execute --all -a 张三 --type=bugfix        # 按条件筛选
speccore execute --all --priority=high --backend    # 后端高优先级
```

### 指定时间自动执行

`schedule create --at` 直接指定时间，守护进程到时自动执行，不需要先放队列。

```bash
speccore schedule create --at "2026-08-10 02:00:00" --all -i Q1 -a 张三 --batch-size=3
speccore schedule create --at "2026-08-10 21:00:00" -t Task-001
speccore schedule list && speccore schedule detail --id=sch-xxx
speccore schedule daemon start          # 启动守护进程
speccore schedule cancel --id=sch-xxx   # 取消
```

### 轻量标记 + 批量手动触发

`--schedule=night` 标记为 queue，之后 `execute --scheduled` 手动触发。

```bash
speccore task new -n "修复登录超时" --type=bugfix --schedule=night
speccore task new --batch-file=bugs.xlsx --type=bugfix --schedule=night
speccore execute --all --scheduled       # 手动触发所有 queue
```

> `execute --all` 跑 todo，`execute --scheduled` 跑 queue，互不干扰。<a name="schedule"></a>

## 场景八：长任务链分批执行

speccore execute --resume

```bash

## 场景十五：需求拆分全流程（全量层 → 期次 → 任务）

**方式一：从 Word/MD 文档导入后拆分**
```bash
# 1. 批量导入各端需求（自动合并到 REQUIREMENT.md）
speccore doc2spec --files "admin.docx=后台管理端,h5.md=后台H5端,web.docx=Web" --iter=Q3

# 2. 预览拆分
speccore iteration split --dry-run

# 3. 执行拆分（自动检测端 + 按端分配）
speccore iteration split
# → Platforms: 后台管理端, 后台H5端, Web          ← 从 INDEX.md 自动检测
# → ## 后台管理端需求 下的 section  → 只建 backend/管理/
# → ## 后台H5端需求   下的 section  → 只建 backend/H5/
# → ## Web端需求       下的 section  → 只建 frontend/Web/

# 4. 手动指定端
speccore iteration split --platforms=web,mini,h5
```

**方式二：从全量需求池拉取**
```bash
# 1. 查看全量需求池
speccore global-status
# → REQ-001  用户认证   待规划

# 2. 拉取需求 → 生成期次
speccore iteration-from-global --reqs=REQ-001,REQ-002 --name=期次-2026-Q3

# 3. 执行拆分
speccore iteration split -I 期次-2026-Q3

# 4. 查看进度
speccore status-panel -I 期次-2026-Q3 --detail
```

## 场景二十四：多开发者并行

**背景**: 张三开发 Task-001，李四开发 Task-002，需要不冲突地并行工作。

**操作**:
```bash
# 张三
git checkout -b 260715-订单管理-zs
vim 期次-Q3/Task-001-订单管理/backend/REQ.md
speccore execute -t Task-001 --force
speccore sync -t Task-001 --detect

# 李四（同时）
git checkout -b 260715-用户认证-ls
vim 期次-Q3/Task-002-用户认证/backend/REQ.md
speccore execute -t Task-002 --force
speccore sync -t Task-002 --detect
```

**关键规则**:

| 规则 | 说明 |
| :--- | :--- |
| 不同 Task | 互不冲突，可完全并行 |
| 同一 Task | 不要两人同时改同一端（backend/frontend） |
| 全局配置 | 改 GLOBAL/* 或 CONSTITUTION 需相互告知 |
| PR 合并前 | 各自跑 `speccore sync --detect` 确认一致 |

**验证**:
```bash
# 检查不同分支各跑各的
speccore status-panel          # 整体进度
speccore health -t Task-001  # 健康度
speccore health -t Task-002
```

## 场景二十六：故障排除

### context.json 损坏/丢失

```bash

## 场景二十七：依赖任务分支管理

依赖任务开发时需要避免实体/组件重复生成。

**原理**：依赖方从被依赖方的分支分叉，自动继承已有代码。

```bash
# 1. 先查看依赖关系
cat 期次-001-Q3/IMPACT.md
# | Task-002: 订单查询 | → | Task-001: 用户管理 | `/api/users` |

# 2. 先执行无依赖的任务
speccore execute -t Task-001 --force
# → 🌿 Created branch: feature/Task-001-用户管理

# 3. 依赖任务自动检测 base（推荐）
speccore execute -t Task-002 --force
# → 🔗 检测到依赖 → 🎯 自动从 Task-001 分叉
# → 🌿 Created branch: feature/Task-002-订单查询 (from feature/Task-001-用户管理)

# 4. 或手动指定 base
speccore execute -t Task-002 --force --base=feature/Task-001-用户管理
```

**结果**：Task-002 分支上已有 Task-001 的 UserController 等代码，不会重复生成。
合并时 Task-002 → main 只带来增量变更。

**默认 base 分支**：在 `.speccore/SETTINGS.md` 中配置：
```yaml
git:
  default_base: develop   # 默认从 develop 分叉（省略则从当前分支）
```

## 场景三十二：技术选型参考 

SpecCore 是 SDD 工具（Spec-Driven Development）工具，但定位不同：

| 场景 | 方案 | SpecCore | 适用场景 |
| :--- | :--- | :--- |
| 从 Word/PRD 导入需求 | ✅ `doc2spec` | ❌ 不支持 |
| 拆分任务 + 自动填充文档 | ✅ 11 份/Task | ✅ 8 文件 |
| 中文意图识别 | ✅ 38 种意图 | ❌ 只英文 |
| Git 分支 + 依赖检测 | ✅ 自动 | ❌ 无 |
| 质量关卡 | ✅ lifecycle 内置 | ❌ 手动 |
| 回滚 | ✅ `rollback` | ❌ 无 |
| 外部 AI 代码生成 | ❌ 模板生成 | ✅ Copilot/Claude |

**选型建议：**
- 团队需要全流程管控 + 中文支持 → SpecCore
- 个人/小团队 + 已有 AI IDE → 
- 两者也可配合：SpecCore 做需求→拆分， 做代码生成

## 场景三十六：外部 AI 协作

**背景**: SpecCore 模板生成基础代码，复杂逻辑想交给外部 AI（Copilot / Claude / Trae）。

```bash
# 输出格式化上下文，粘贴到对应的 AI 工具
speccore execute -t Task-001 --agent=copilot
# → 🤖 Agent 模式: copilot
# → --- 复制以下内容到 copilot ---
# → Based on the spec below, generate production code:
# → ## Task-001 — 订单管理
# → [REQ.md + TECH.md + CONSTITUTION 规则]
# → --- END ---

speccore execute -t Task-001 --agent=trae
# → 中文 prompt，带宪法规则和 API 契约

# 支持 7 种工具
speccore execute -t Task-001 --agent=cursor     # Cursor
speccore execute -t Task-001 --agent=windsurf   # Windsurf
speccore execute -t Task-001 --agent=codebuddy  # WorkBuddy
```

**原理**: 不直接调用外部 AI，而是输出标准化上下文（REQ.md + TECH.md + TEST.md + Constitution），用户粘贴到对应工具。
