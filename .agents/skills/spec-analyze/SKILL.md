# SpecCore Analyze — 深度需求分析

> **定位**：AI 驱动的需求分析引擎。读取 010-requirements/ 中的需求文档，结合 CONSTITUTION.md 中定义的技术栈和规范，生成结构化的分析报告。
>
> **核心能力**：需求拆解 → 技术映射 → 风险识别 → 依赖分析 → 输出 ANALYSIS.md

## 详细执行步骤

### Step 1: 上下文加载
```
1. 读取 .speccore/CONSTITUTION.md
   - 获取技术栈定义（语言/框架/数据库）
   - 获取端映射（工程 → 需求端对应关系）
   - 获取命名规范和异常码体系

2. 读取 .speccore/local/context.json
   - 获取当前迭代名
   - 获取当前任务状态

3. 扫描 010-requirements/ 目录
   - 列出所有需求功能（user-auth/, room-booking/, ...）
   - 读取每个 README.md 的内容
   - 收集所有 API 接口定义
   - 收集所有数据模型定义
   - 记录涉及的端
```

### Step 2: 需求拆解
```
对每个需求功能进行评估：

1. API 接口清单
   - 汇总所有 API（方法 + 路径 + 说明）
   - 检测是否缺少关键字段（请求体、响应体、错误码）
   - 检查是否符合 CONSTITUTION 中的命名规范
   - 标记不规范项 → ⚠️

2. 数据模型清单
   - 提取所有实体定义
   - 检查字段类型是否明确
   - 检查是否缺少约束（NOT NULL、UNIQUE、DEFAULT）
   - 检查命名是否符合 snake_case 规范

3. 跨端差异分析
   - 同一需求在不同端的表现
   - API 在不同端的调用方式差异
   - UI/UX 差异

4. 需求完整性评分
   - ✅ 完整：API + 数据模型 + 业务规则齐全
   - ⚠️ 部分：缺少某些细节
   - ❌ 不足：关键信息缺失
```

### Step 3: 技术映射
```
根据 CONSTITUTION.md 的技术栈定义：

1. 为每个 API 推断实现位置
   - Java/Spring → Controller + Service + Repository
   - TypeScript/NestJS → Controller + Service + Entity
   - Go/Gin → Handler + Service + Model

2. 为每个数据模型生成 DDL 骨架
   - 表名 → snake_case 复数
   - 字段 → 对应数据库类型
   - 索引 → 根据查询模式建议

3. 识别代码模块
   - 需要新增的模块
   - 需要修改的模块
   - 可以复用的模块
```

### Step 4: 风险与依赖分析
```
识别以下风险：

1. 技术风险
   - 新技术栈的学习成本
   - 性能瓶颈点（高并发、大数据量）
   - 安全风险（权限、注入、数据泄露）

2. 依赖风险
   - 外部服务依赖（支付、短信、推送）
   - 内部服务依赖（其他微服务）
   - 第三方库依赖

3. 进度风险
   - 估算工作量（人天）
   - 识别关键路径
   - 标记阻塞项

4. 质量风险
   - Spec 覆盖不足的功能
   - 缺少测试场景定义
   - 缺少异常处理定义
```

### Step 5: 输出分析报告
```
向用户展示分析摘要：

📊 需求分析完成 — {迭代名}
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 需求功能: {n} 个
🔌 API 接口: {n} 个（⚠️ {n} 个缺少响应定义）
🗄️ 数据模型: {n} 个（⚠️ {n} 个缺少字段约束）
🏗️ 涉及工程: {工程列表}
👥 涉及端: {app/h5/miniapp/admin}
⚠️ 风险: {n} 项（高: {n}, 中: {n}, 低: {n}）
📈 完整性: {percentage}% 
📤 输出: 020-specs/{端}/ANALYSIS.md
👉 下一步: speccore iteration split -I {迭代名}
```

## 输出 CLI 命令

确认分析完成后，输出：

```bash
speccore analyze -I {迭代名} [--task {任务名}]
```

### 参数说明
| 参数 | 含义 | 必需 |
| :--- | :--- | :--- |
| -I | 迭代名 | 是 |
| --task | 分析特定任务 | 否 |
| --deep | 深度分析（含代码扫描） | 否 |

---

## 常见场景

| 场景 | 分析重点 |
| :--- | :--- |
| 新迭代开始 | 全量需求拆解，技术映射，工作量估算 |
| 单个任务分析 | 聚焦该任务的 API 和数据模型 |
| 需求变更后 | 影响范围分析，变更对比 |
| 代码审查 | Spec vs Code 一致性检查 |
