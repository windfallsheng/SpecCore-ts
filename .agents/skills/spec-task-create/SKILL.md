# SpecCore Task Create — 交互式任务创建（高阶 Skill）

> **你负责**: 接收任意输入 → 内容澄清 → 智能命名 → 生成 REQUIREMENT.md → 推荐下一步。
> **分支规则**: 创建任务后，Git 分支名 = `feature/Task-{id}-{任务名}`，与任务目录名完全一致。

## 支持的任务类型

| 类型 | 说明 | 典型输入 | 澄清要点 |
| :--- | :--- | :--- | :--- |
| `feature` | 新增功能 | "做登录功能" | 目标用户、交互流程、涉及API |
| `bugfix` | Bug修复 | "修复支付bug" | 复现步骤、影响模块、优先级 |
| `research` | 技术调研 | "调研微服务方案" | 方向、产出物、交付形式 |
| `review` | 代码审查 | "审查Task-001代码" | 范围（文件/Task/分支）、关注点 |
| `test` | 测试任务 | "补充单元测试" | 覆盖模块、测试框架、覆盖率目标 |
| `docs` | 文档任务 | "更新API文档" | 文档范围、目标读者、格式 |
| `refactor` | 重构任务 | "重构订单模块" | 范围、目标架构、兼容要求 |

### review 类型 — 代码审查报告

1. 读取指定 Task 的 REQUIREMENT.md + ANALYSIS.md
2. 读取对应代码文件（通过目录结构推断）
3. 你自己审查并生成 REVIEW_REPORT.md:

```
# 代码审查报告

## 审查信息
| 审查人 | AI | 日期 | xxx | 范围 | Task-001, Task-002 |

## 需求符合度
| 需求项 | 状态 | 说明 |
| 登录API | ✅ 符合 | POST /api/login |

## 发现的问题
| 严重度 | 文件 | 行 | 问题 | 建议 |
| P0 | Auth.java | 23 | SQL注入 | 使用PreparedStatement |
| P2 | User.java | 45 | 缺少javadoc | 添加注释 |

## 质量评分
- 代码结构: 8/10
- 安全性: 6/10  
- 可维护性: 7/10
- 综合: 7/10

## 行动项
- [ ] P0: 修复SQL注入
- [ ] P2: 补充文档
```

### test 类型 — 测试执行报告

1. 读取 ANALYSIS.md 提取 API 定义、数据模型、业务规则
2. 读取已有测试用例（如有）
3. 你自己生成 TEST_REPORT.md:

```
# 测试执行报告

## 测试概览
| 总用例 | 通过 | 失败 | 跳过 | 覆盖率 |
| 12 | 10 | 1 | 1 | 83% |

## 测试用例
| ID | 描述 | 输入 | 期望 | 实际 | 状态 |
| TC01 | 正常登录 | admin/123 | 200 | 200 | ✅ |

## 失败详情
### TC05 - 密码为空
- 期望: 400 + "密码不能为空"
- 实际: 500 + Internal Error
- 建议: AuthController line 23 缺少空值检查

## 边界测试
| 场景 | 结果 |
| 超长密码(1000字符) | ⚠️ 未测试 |
| SQL注入 | ⚠️ 未测试 |
```

### 其他类型（可扩展）

| deploy | 部署任务 | 生成部署检查单 + 环境配置 |
| security | 安全审计 | OWASP Top 10 检查报告 |
| performance | 性能优化 | 瓶颈分析 + 优化建议 |

```
你根据用户描述，自己提取核心概念并翻译为英文（≤3 个单词）:
1. 提取用户明确给出的编号/日期/人名/优先级 → 必须保留
2. 保留用户原文的关键中文描述词
3. 追加你翻译的英文关键词
4. 组合: {保留的ID}-{中文关键}-{你的英文关键词}

示例:
用户: "修复登录页bug"      → 你: Task-003-修复登录页-login-bug
用户: "260806 zhangsan支付问题" → 你: Task-004-260806-zhangsan-支付-payment
用户: "P0:数据库超时"       → 你: Task-005-P0-数据库超时-db-timeout
```

确认时展示你生成的名称 → 用户可修改 → 不改则用这个名字

## 内容澄清 （< 80 字时必须提问）

```
Bug 类:
  1. 复现步骤？
  2. 影响模块？
  3. 优先级？(P0/P1/P2)

功能类:
  1. 目标用户？
  2. 核心流程？
  3. 涉及 API？

一次最多问 3 个问题，等用户回复后继续。
```

## 执行流程

```
1. 接收输入 → 判断长度 → <80字必须澄清

2. 生成 REQUIREMENT.md:
   属性表(编号/类型/优先级/迭代/负责人) + 描述 + 验收标准

3. Write 文件 → 推荐:
   speccore analyze --prompt -I {iter} --task {taskId}
   speccore execute --prompt -t {taskId}
```

## 退出码

| exitCode | 行动 |
| :--- | :--- |
| 0 | 创建完成 → 推荐 |
| 11 | 追问澄清 |
| 其他 | [重试/跳过] |
