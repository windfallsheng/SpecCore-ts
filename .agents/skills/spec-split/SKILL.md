# SpecCore Split — 智能任务拆分

> **定位**：基于需求分析结果，按端、按功能模块、按依赖关系，将需求拆分为可独立执行的开发任务。
> 
> **核心能力**：智能分组 → 人员分配 → 依赖检测 → 生成 Task 结构

---

## 详细执行步骤

### Step 1: 加载上下文
```
1. 读取 020-specs/ 下所有端的 ANALYSIS.md
2. 读取 STAFFING.md 获取人员配置
3. 读取 CONSTITUTION.md 获取端映射
4. 统计：总 API 数、总实体数、涉及端数
```

### Step 2: 按端智能分组
```
分组策略（优先级从高到低）：

1. 按端（app/h5/miniapp/admin）
   - 不同端 → 独立 Task（可并行开发）

2. 按功能模块（user-auth, room-booking, ...）
   - 同一端内按功能再细分
   - 功能独立 → 独立 Task
   - 功能耦合 → 合并 Task

3. 按 API 数量控制
   - API ≤ 3 → 合并到相关 Task
   - API 4~8 → 独立 Task
   - API > 8 → 拆分为多个 Task

4. 前置/公共任务
   - 数据模型定义 → 单独的 Task-000（所有 Task 的前置依赖）
   - 公共组件 → 单独的 Task
```

### Step 3: 人员智能分配
```
分配策略：

1. 读取 STAFFING.md：
   | 成员 | 平台方向 | 投入比例 |
   | :--- | :--- | :--- |
   | 张三 | app, h5 | 80% |
   | 李四 | admin, miniapp | 70% |

2. 匹配规则：
   - 端匹配：app 端任务 → 张三
   - 负载均衡：每人任务量接近
   - 技能匹配：根据技术栈分配

3. 展示分配方案 → 询问用户确认
   ┌─────────────────────────────────────────┐
   │ 📊 任务分配预览                          │
   ├──────────┬────────┬─────────┬───────────┤
   │ 任务      │ 端      │ API 数  │ 负责人    │
   ├──────────┼────────┼─────────┼───────────┤
   │ Task-001  │ app    │ 6       │ 张三       │
   │ Task-002  │ h5     │ 4       │ 张三       │
   │ Task-003  │ miniapp│ 5       │ 李四       │
   │ Task-004  │ admin  │ 3       │ 李四       │
   └──────────┴────────┴─────────┴───────────┘
   确认拆分？[y/n]
```

### Step 4: 依赖关系检测
```
检测以下依赖并标记：

1. API 依赖
   - Task A 的 API 被 Task B 调用 → B 依赖 A
   
2. 数据模型依赖
   - Task A 和 Task B 共享同一实体 → 建议先完成实体定义
   
3. 基础设施依赖
   - 认证/授权 → 其他 Task
   - 数据库初始化 → 所有 Task
   - 公共 API/组件 → 相关 Task

4. 输出依赖图：
   Task-000（数据模型）
     ├── Task-001（app 认证）
     │     └── Task-003（app 预订）
     ├── Task-002（h5 认证）  
     │     └── Task-004（h5 预订）
     └── Task-005（admin 管理）
```

### Step 5: 输出 Task 结构
```
预览每个 Task 的内容结构：

Task-001: app 用户认证
├── 所属端: app
├── 负责人: 张三
├── API 数: 3
│   ├── POST /api/auth/login
│   ├── POST /api/auth/register
│   └── GET /api/auth/me
├── 依赖: Task-000（数据模型）
└── 工作量: 预估 2 人天
```

---

## 输出 CLI 命令

```bash
speccore iteration split -I {迭代名} [--owner {负责人}]
```

### 参数说明
| 参数 | 含义 | 必需 |
| :--- | :--- | :--- |
| -I | 迭代名 | 是 |
| --owner | 指定负责人（覆盖 STAFFING.md） | 否 |
| --dry-run | 预览模式（不创建目录） | 否 |

---

## 拆分质量检查清单

- [ ] 每个 Task 是否可独立开发？
- [ ] API 分配是否合理（不多不少）？
- [ ] 人员分配是否均衡？
- [ ] 依赖关系是否清晰？
- [ ] 是否有遗漏的 API？
- [ ] 是否有遗漏的数据模型？
- [ ] Task 命名是否规范（Task-NNN）？
- [ ] PROJECT_GRAPH.md 是否已更新？
