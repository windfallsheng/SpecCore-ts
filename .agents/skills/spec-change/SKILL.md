# SpecCore Change — 需求变更管理

> **定位**：记录需求变更、分析影响范围、重新生成受影响的任务代码。
> **核心能力**：变更登记 → 影响分析 → 代码更新 → 同步 Spec

---

## 工作流程

```
用户描述变更
      │
      ▼
┌─────────────────────────────────────────┐
│ Phase 1: 变更记录                        │
│ • 记录变更描述                            │
│ • 关联到具体 Task                         │
│ • 记录变更原因                            │
│ • 写入 CHANGELOG                         │
└──────────────┬──────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────┐
│ Phase 2: 影响分析                        │
│ • 哪些 API 受影响                         │
│ • 哪些数据模型受影响                      │
│ • 哪些 Task 受影响                        │
│ • 哪些代码文件需要修改                    │
└──────────────┬──────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────┐
│ Phase 3: 变更执行                        │
│ • 更新 Spec 文档（REQ.md/TECH.md）        │
│ • 重新生成受影响代码                      │
│ • 更新 API_CONTRACT.yaml                  │
└──────────────┬──────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────┐
│ Phase 4: 变更总结                        │
│ • 变更内容摘要                            │
│ • 受影响文件列表                          │
│ • 建议的验证步骤                          │
└─────────────────────────────────────────┘
```

## 详细步骤

### Step 1: 变更记录
```
1. 收集变更信息
   - 变更描述（用户输入的自然语言）
   - 关联 Task（若用户未指定，从 context.json 读取）
   - 变更类型（feature / bugfix / optimization / breaking）

2. 写入变更记录
   - 追加到 Task 的 REQ.md 底部
   - 追加到 PROJECT_GRAPH.md 的变更历史

3. 格式：
   ## 变更记录
   
   | 日期 | 变更内容 | 类型 | 影响范围 |
   | :--- | :--- | :--- | :--- |
   | 2026-08-07 | 增加手机号登录限制 | feature | AuthController, UserService |
```

### Step 2: 影响分析
```
1. 分析变更描述中的关键词
   - "增加 API" → 需要新增 Controller 方法
   - "修改字段" → 需要更新 Model + DDL
   - "删除功能" → 需要移除相关代码
   - "调整业务规则" → 需要更新 Service 逻辑

2. 识别影响的 Spec 文件
   - REQ.md: API 表格、数据模型
   - TECH.md: 技术方案
   - API_CONTRACT.yaml: 接口定义

3. 识别影响的代码文件
   - Controller/Handler: 路由注册
   - Service: 业务逻辑
   - Model/Entity: 数据结构
   - DTO: 请求/响应
   - Test: 测试用例

4. 展示影响分析 → 用户确认
   📊 变更影响分析
   ━━━━━━━━━━━━━━━━━━
   📝 变更: 增加手机号登录限制（每小时最多5次）
   🎯 目标 Task: Task-001
   
   📄 影响的 Spec:
   ✅ REQ.md: 更新 API 表格
   ✅ TECH.md: 更新限流方案
   
   💻 影响的代码:
   ✅ AuthController.java: 添加限流检查
   ✅ AuthService.java: 添加登录次数计数
   ✅ LoginRequest.java: 无需修改
   ⚠️ AuthServiceTest.java: 需要新增测试用例
```

### Step 3: 变更执行
```
1. 更新 Spec 文档
2. 运行 speccore execute -t {task} --force（重新生成代码）
3. 运行变更后的测试

4. 同步到关联 Task：
   如果影响范围涉及其他 Task → 提醒用户
```

---

## 输出 CLI 命令

```bash
speccore change "{变更描述}" --task {任务编号} [--type {变更类型}]
```

### 参数说明
| 参数 | 含义 | 必需 |
| :--- | :--- | :--- |
| 变更描述 | 自然语言描述变更内容 | 是 |
| --task | 关联的任务编号 | 否 |
| --type | 变更类型 (feature/bugfix/optimize/breaking) | 否 |
