# spec-done — 任务归档收尾（专属逻辑）

> **定位**：`/done` 快捷入口的专属预处理层
> **原则**：不影响 `speccore ask` 的意图识别能力

---

## 调用方式

```
/done [参数]
/done --task Task-001
/done --all -I Iteration-001
/done --task Task-001 --interactive
```

---

## 执行流程

```
用户输入 /done [参数]
        │
        ▼
┌───────────────────────────────────────┐
│ Step 1: 参数提取                        │
│ 从用户输入提取 task/iteration/all 等     │
└───────────────┬───────────────────────┘
                │
        参数缺失？
                │
        是 ──► 输出交互式提示
                │
        否 ──► 继续
                │
                ▼
┌───────────────────────────────────────┐
│ Step 2: 前置校验                        │
│ - Task 是否存在？                       │
│ - 依赖任务是否已完成？                  │
│ - feature 分支是否已合并？              │
│ - 代码是否已提交？                      │
└───────────────┬───────────────────────┘
                │
        校验失败？
                │
        是 ──► 输出问题 + 修复建议
                │
        否 ──► 继续
                │
                ▼
┌───────────────────────────────────────┐
│ Step 3: 调用 speccore ask               │
└───────────────────────────────────────┘
```

---

## Step 1: 参数提取

| 参数 | 短名 | 长名 | 必填 | 说明 |
|:---|:---|:---|:---|:---|
| task | -t | --task | 否 | 目标 Task（支持逗号分隔批量）|
| iteration | -i | --iteration | 否 | 目标迭代名 |
| all | -a | --all | 否 | 自动扫描已完成任务批量归档 |
| skipValidate | - | --skip-validate | 否 | 跳过校验 |
| skipSync | - | --skip-sync | 否 | 跳过全局同步 |
| interactive | - | --interactive | 否 | 交互式确认 |
| prompt | -p | --prompt | 否 | 输出验收总结 Prompt |
| response | -r | --response | 否 | 接收 AI 验收总结 |

```bash

# 如果不存在 → 提示可用 Task 列表
```

### 3.2 依赖任务完成性检查
```bash
# 读取 Task/.meta/dependencies
# 检查依赖的 Task 是否已完成（status=done）
# 如果有未完成依赖 → 提示用户先完成依赖任务
```

### 3.3 feature 分支合并检查
```bash
# 检查 feature/Task-XXX 分支是否已合并到 main
# 如果未合并 → 提示用户先合并或创建 PR
```

### 3.4 代码提交检查
```bash
# 检查 Task 对应的 feature 分支是否有未提交代码
# 如果有 → 提示用户先提交代码（speccore pr）
```

### 3.5 扫描已完成任务（--all 模式）
```bash
# 扫描 030-tasks/ 下 status=done 的任务
```

```bash
execute_command("speccore ask '归档 Task-XXX...'")
```

## 核心流程（保留）

```
用户说 "归档 Task-001"
        │
        ▼
┌─ 1. 前置校验 ────────────────────────────────┐
│  - Task 存在？                               │
│  - 依赖任务已完成？                           │
│  - feature 分支已合并？                       │
│  - 代码已提交？                              │
└───────────────┬────────────────────────────────┘
                │
                ▼
┌─ 2. 执行收尾（5 步）─────────────────────────┐
│  1. validate  — 规范合规校验                  │
│     → 发现问题？warn 并继续（可 --strict 阻断）│
│  2. archive   — 任务归档                      │
│     → 移动 Task 到归档目录                     │
│  3. merge     — 新增需求合并回原文档            │
│     → 更新 REQUIREMENT.md                     │
│  4. sync      — 同步到全局层                   │
│     → 更新 GLOBAL/INDEX.md                    │
│  5. audit     — 生成审计摘要                   │
│     → 生成 RETRO.md                          │
└───────────────┬────────────────────────────────┘
                │
                ▼
┌─ 3. 后续引导 ────────────────────────────────┐
│  归档完成 → 引导用户 "可以开始 retro 复盘"     │
│  或 "开始下一个 Task"                         │
└───────────────────────────────────────────────┘
```

## 铁律

1. **依赖任务必须先完成** — 不允许跳过依赖直接归档
2. **feature 分支必须先合并** — 防止代码丢失
3. **validate 发现问题要提示** — 即使不阻断也要明确告知
