# SpecCore spec2doc — AI 排版 + Pandoc 导出 + 质量验证

> **核心设计**：AI 负责"内容编排和质量把控"，Pandoc 负责"格式转换"。
> AI 在转换前验证 Spec 文档的完整性，在转换后校验输出文档的质量。
> 本 Skill 实现了"编译 + 排版 + 校验"的完整出版流水线。

---

## 1. 触发条件

用户说以下关键词时激活本 Skill：
- "导出文档"、"生成 Word"、"导出 PDF"、"输出报告"
- "spec2doc"、"导出 {迭代} 的文档"
- "把 Spec 转成 Word/PDF/PPTX"
- "生成交付文档"、"打包文档"

## 3. 执行步骤（详细版）

### Phase 1: AI 内容验证

```
1. 收集所有 Spec 源文件
   - 根据 --iteration 或 --task 参数定位文件
   - 默认收集：010-requirements/REQUIREMENT.md + 020-specs/ANALYSIS.md
   - --all 模式：收集所有 Task 的 REQ.md + TECH.md + TASK.md

2. 逐项审计：
   ┌──────────────────┬────────────────────────────────────┐
   │ 审计项           │ 检查方式                            │
   ├──────────────────┼────────────────────────────────────┤
   │ 文档元信息       │ 标题、版本、日期、作者是否完整       │
   ├──────────────────┼────────────────────────────────────┤
   │ API 定义完整度   │ 每个 API 是否都有请求/响应示例       │
   ├──────────────────┼────────────────────────────────────┤
   │ 数据模型覆盖     │ 所有实体是否都有字段说明              │
   ├──────────────────┼────────────────────────────────────┤
   │ 交叉引用有效性   │ [链接] 指向的文件是否存在             │
   ├──────────────────┼────────────────────────────────────┤
   │ 占位符残留       │ TODO、TBD、XXX 等未完成标记          │
   ├──────────────────┼────────────────────────────────────┤
   │ 代码块完整性     │ 代码块是否有语言标记、是否完整       │
   ├──────────────────┼────────────────────────────────────┤
   │ 图片引用有效性   │ 引用的图片文件是否存在               │
   └──────────────────┴────────────────────────────────────┘

3. 输出审计报告 → 展示给用户，询问是否继续导出
   - 若有严重问题（如 API 定义缺失），建议先补全再导出
   - 若只有小问题，标记并继续
```

### Phase 2: AI 结构编排

```
1. 生成编排后的临时 Markdown（.tmp_export_structured.md）：

   ---
   封面：
   # {项目名称}
   ## {迭代名称} — 技术文档
   ### 版本 {version} | {date}
   ### 状态：{status}
   
   ---
   目录：
   [由 pandoc 自动生成]
   
   ---
   1. 项目概述
      - 业务背景
      - 技术架构概览
      - 涉及的平台端
   
   2. 需求详情
      2.1 {功能A}
          2.1.1 功能描述
          2.1.2 涉及的 API
          2.1.3 数据模型
          2.1.4 UI/UX 说明
      2.2 {功能B}
          ...
   
   3. 系统分析
      3.1 技术方案
      3.2 难点与风险
      3.3 依赖关系
   
   4. 开发任务
      4.1 Task-001: {任务名}
      4.2 Task-002: {任务名}
      ...
   
   5. 附录
      5.1 API 接口完整清单
      5.2 数据模型完整定义
      5.3 术语表
      5.4 变更记录

2. 处理特殊元素：
   - Mermaid 图表 → 标记为需要后处理渲染
   - HTML 表格 → 转换为 Markdown 表格
   - 嵌套列表 → 规范化缩进
   - 代码块 → 确保有正确的语言标记
```

### Phase 3: Pandoc 机械转换

```
1. 检测 pandoc 可用性
   - 不可用 → 转换为 AI 纯手工模式（仍有格式，但排版需人工微调）

2. 执行转换命令：
   LANG=zh_CN.UTF-8 pandoc \
     "{tmp_structured_md}" \
     -f gfm \
     -t {format} \
     --wrap=none \
     --toc \
     --toc-depth=3 \
     --metadata title="{项目名称} - {迭代名称}" \
     --metadata author="{团队名称}" \
     --metadata date="{日期}" \
     --resource-path=".:{iter_dir}" \
     -o "{output_file}"

   可选参数：
   --reference-doc "{template}.docx"    # 使用自定义模板
   --pdf-engine=xelatex                  # PDF 中文支持
   --highlight-style=tango               # 代码高亮主题

3. 处理转换错误：
   - 超长行警告 → 忽略（已用 --wrap=none）
   - 图片找不到 → 列出缺失图片，询问是否跳过
   - 字体缺失 → 建议安装对应字体
```

### Phase 4: AI 后处理

```
仅适用于 .docx 格式（PDF/HTML 由 pandoc 一次性完成）：

1. 读取 pandoc 生成的 .docx 文件（AI 可读 docx）

2. 逐项优化：
   ┌──────────────────┬──────────────────────────────────────┐
   │ 优化项           │ 处理方式                              │
   ├──────────────────┼──────────────────────────────────────┤
   │ Mermaid 图表     │ 解析 Mermaid 代码 → 渲染为图片 →     │
   │                  │ 替换文档中的代码块                    │
   ├──────────────────┼──────────────────────────────────────┤
   │ 中文排版         │ 首行缩进 2 字符                       │
   │                  │ 中英文间加空格                        │
   │                  │ 段间距调整                            │
   ├──────────────────┼──────────────────────────────────────┤
   │ 标题样式         │ Heading 1/2/3 使用统一字体和颜色      │
   ├──────────────────┼──────────────────────────────────────┤
   │ 表格样式         │ 统一边框线、斑马纹                    │
   ├──────────────────┼──────────────────────────────────────┤
   │ 页眉页脚         │ 页眉：项目名 + 迭代名                 │
   │                  │ 页脚：页码 + 总页数                   │
   ├──────────────────┼──────────────────────────────────────┤
   │ 封面美化         │ 加项目 Logo、分隔线                   │
   ├──────────────────┼──────────────────────────────────────┤
   │ 代码块样式       │ 等宽字体、浅灰背景                    │
   └──────────────────┴──────────────────────────────────────┘

3. 保存优化后的文档，覆盖 pandoc 原始输出
```

### Phase 5: 质量验证

```
交叉验证输出文档：
1. 逐页检查关键内容是否存在
2. 确认所有 API 表格完整
3. 确认所有数据模型字段不丢失
4. 检查图片清晰度
5. 检查文件大小是否合理

输出验证报告：
✅ 文档导出完成 — 质量验证报告
━━━━━━━━━━━━━━━━━━━━━━━━
📄 输出: 会议室预订v2-技术文档.docx (2.8MB)
📊 内容: 45 页, 6 章, 18 个 API, 5 个数据模型
🔍 质量验证:
   ✅ 章节完整性: 6/6 通过
   ✅ API 表格: 18/18 完整
   ✅ 数据模型: 5/5 完整
   ✅ Mermaid 图表: 3 张已渲染
   ✅ 图片引用: 12 张全部嵌入
   ⚠️ 中文排版: 已由 AI 优化
📋 建议: 可在 Word 中微调字体大小和页边距
```

## 4. 参数处理规则

| 参数 | 含义 | 获取方式 | 默认值 |
| :--- | :--- | :--- | :--- |
| --iteration | 迭代名 | context.json 或询问 | 当前迭代 |
| --task | 指定 Task | 用户输入 | 全部 Task |
| --file | 指定单个 .md | 用户输入 | - |
| --format | 导出格式 | 用户输入 | docx |
| --output | 输出文件名 | 自动生成 | 项目名-迭代名 |
| --all | 全量导出 | flag | false |
| --template | 参考模板 | 用户提供 .docx | 无 |
| --no-ai-postprocess | 跳过 AI 后处理 | flag | false |

---

## 5. 格式支持矩阵

| 格式 | Pandoc 转换 | AI 后处理 | 推荐场景 |
| :--- | :--- | :--- | :--- |
| .docx | ✅ | ✅ 全力后处理 | 正式交付文档 |
| .pdf | ✅ | ⚠️ 有限（pandoc一次性） | 快速分享、评审 |
| .html | ✅ | ✅ 可深度定制 | 在线预览、Wiki |
| .pptx | ✅ | ⚠️ 有限 | 演示汇报 |

## 6. 输出命令模板

确认无误后，输出 CLI 命令：

```bash
# 基础导出
speccore spec2doc -i "{iteration}" -o "{output}.docx"

# 全量导出
speccore spec2doc -i "{iteration}" --all -o "{output}.docx"

# 按 Task 导出
speccore spec2doc -i "{iteration}" --task "{task}" -o "{output}.docx"

# 导出 HTML（适合在线预览）
speccore spec2doc -i "{iteration}" --all -f html -o "{output}.html"
```

AI 对话中可执行的额外优化：
- Mermaid 渲染：用 `show_widget` 渲染图表，截图后嵌入
- 中文排版：逐段检查并修正
- 封面设计：生成定制化的首页
